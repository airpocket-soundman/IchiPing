走査音考察 NN 検討 / 検討段階

1 個のセンサで返ってくる応答を最大限「判別可能」にするには、 どんな音を 1 発 Ping として撃つべきか。 励振信号の候補を物理・情報理論・推論器の都合の 3 軸で比較する。
7 信号方式を比較 14 / 32 実効状態を判別 200–6k Hz 帯域目標
本ページの位置づけ: 走査音（物理 Ping）の設計を、物理モデル・情報理論・NN 推論器の都合の 3 軸で考察する。 共鳴駆動推論戦略（旧「励振パターン設計」ノート）の内容もすべてここに統合した。

1. 何を判別したいのか — 観測上限から逆算

状態空間は窓 3 + 扉 2 = 5 ビット 32 状態 あるが、 扉が閉まると向こう側は音響的に遮断されるため、実効的に区別できるのは 14 状態のみ（[index.html のフロアプラン考察] および [observability.svg] 参照）。 走査音設計の最終的な評価基準は「この 14 状態を判別する識別力」であって、 単に「広帯域で SNR が高い」ことではない。

条件判別したい変数状態数
扉 AB 閉窓 a（扉 AB 自体は必ず判別したい）2
扉 AB 開, 扉 BC 閉窓 a, 窓 b, 扉 BC4
扉 AB 開, 扉 BC 開窓 a, 窓 b, 窓 c8

ここから出る示唆: 扉 AB の開閉判別は必須・最優先（誤ると後段の窓判別の前提が崩れる）。 扉 AB のモード分裂は Room A 単独 vs A+B 結合の差で、典型的に 低域（300–800 Hz） に大きな変化が出ると予想される。よって低域のエネルギーは確実に投入する必要がある。

1.A 物理モデル — 期待される周波数応答の変化

1/N 模型の 3 部屋構造（各室 ~30 cm）の基本モード周波数は次式で予測できる。 

f_lmn = (c/2) × √[(l/Lx)² + (m/Ly)² + (n/Lz)²]
c = 343 m/s, L = 0.3 m → f_100 ≈ 572 Hz

この帯域は MAX98357A + 0.25 W 8 Ω スピーカが綺麗に出せる 500 Hz–6 kHz と一致し、 低次モードを確実に駆動できる。状態変化が音響特性に与える効果は次の 4 通り:

状態変化物理現象周波数特性への影響
窓 a/b/c 単独開 壁の境界条件: 剛壁（圧力腹）→ 開口（圧力節） その壁を腹/節とするモードが 半波長分シフト
窓開 → 放射損失 Q 値低下 モード幅広化、RT60 短縮
扉 AB/BC 開 隣接室と音響結合 単一ピーク → 対称/反対称ペアに分裂
扉 + 窓組合せ カップリング + 損失の相互作用 線形和ではない、非自明な周波数応答

特に 扉開閉のモード分裂は判別性が高いと予想される — 単一ピークが 2 本に割れ、 分裂幅が結合の強さに依存する。NN への入力としても明瞭な特徴になる。

Helmholtz 共鳴は使えない: 窓開口の Helmholtz 共鳴は数十 Hz と低すぎ、 MAX98357A + 0.25 W スピーカでは駆動できない。室内モード由来の特徴のみを使う。

2. 候補となる走査音 6 系統

2.1 ESS (Exponential Sine Sweep) + Farina 逆フィルタ

ログ掃引音を撃ち、PC 側で逆フィルタ畳み込みにより線形 RIR を分離抽出。 Farina 2000 の標準手法。

  • 長所: 高 SNR、低域に時間を多く割ける、非線形歪みを時間軸で分離可能、計測理論の蓄積が厚い
  • 短所: 1 計測あたり 1–3 秒必要、PC 側に逆フィルタの実装が要る
  • NN への渡し方: 抽出した RIR を時間波形のまま、または log-mag スペクトルで投入

2.2 Linear chirp（線形掃引）

線形に周波数を上げる掃引。実装が最も単純。

  • 長所: MCU 内 chirp 生成が三角関数 1 回で済む（現 firmware/shared/source/dummy_audio.c で実装済み）
  • 短所: 低域の SNR が低い（時間あたりの帯域占有が一定なので低域に時間を投入できない）
  • NN への渡し方: 整合フィルタで圧縮 → スペクトル化

2.3 共鳴周波数狙い撃ち（マルチトーン）

3 部屋の物理モード周波数を予測し、その周辺だけに集中したマルチトーンを撃つ。 例: f₁₀₀ ≈ 572 Hz, f₂₀₀ ≈ 1.14 kHz, f₁₁₀ ≈ 808 Hz 周辺。

  • 長所: 判別性の高い帯域に全エネルギーを投入できる、解釈性が高い
  • 短所: 模型寸法のばらつきに脆い、汎化性に欠ける、未知の状態への対応力低い
  • NN への渡し方: 各トーンの振幅・位相を直接特徴量に

2.4 MLS / Schroeder 多周期音

最長系列（MLS）や Schroeder 位相による低クレストファクタの雑音的信号を撃ち、 循環相関でインパルス応答を抽出。

  • 長所: クレストファクタが小さく、SPK の歪みを抑えながら高い平均パワーを入れられる。背景雑音的に「聞こえない」
  • 短所: 非線形歪みが時間軸に折り返し雑音として現れる
  • NN への渡し方: 抽出 RIR を ESS と同様に

2.5 短時間 click / 短パルス

数 ms の鋭いインパルス。最古典的な RIR 計測。

  • 長所: 実装最簡、平均レイテンシ最小
  • 短所: SNR が極めて低い、SPK 過渡応答の影響が大、低域出力が苦しい（45 mm スピーカでは特に）
  • NN への渡し方: 生波形 → スペクトル

2.6 ゲート式トーンバーストスイープ

個別周波数を短時間だけ鳴らし、続く無音区間で純粋な残響だけを観測する。 時間軸で励振 (ON) と残響観測 (OFF) を完全分離するため、逆フィルタなしに 「周波数 × 残響強度」マトリクスが直接取れる。 

時間軸:
[500Hz 100ms ON][100ms OFF][550Hz 100ms ON][100ms OFF]...
                  ↑ 完全無音 = 残響だけが録れる
  • 長所: ON/OFF 完全分離なので OFF 中の SNR は環境雑音と量子化のみで律速。 解釈性が極めて高い（「この周波数を撃ったら、これだけ長く鳴る」が直接見える）。 PC 側解析は OFF 区間を切り出して RMS / FFT するだけ — 逆フィルタ実装不要
  • 長所: 既存の pulse 型 （firmware/shared/include/pattern_lib.h） でそのまま実現可能。ファーム拡張は MAX_TONES_PER_PULSE と COL_WINDOW_MAX_MS の上限引き上げのみ
  • 短所: 1 サンプルあたり時間がかかる（例: 110 周波 × 200 ms = 22 秒）。 キャラクタリゼーション（オフライン）には向くが、本番推論には不向き
  • NN への渡し方: 周波数別 RMS の列（110 dim）、または各 OFF 区間の短時間スペクトル

2.7 ホワイトノイズ + 出力スペクトル直読（ROI 発見の最短ルート）

全帯域を 連続的に同時励振し、定常状態の出力スペクトルから直接 |H(f)|² を読む。 Linear chirp や ESS のように時間-周波数を 1 対 1 対応させる必要がないので、 「どの周波数が共鳴しているか」を見るだけなら最も直接的で簡単。 

連続励振 x(t) ≈ 白色雑音（平坦スペクトル）
出力 y(t) = x(t) ⊗ h(t) + noise
定常状態で E[|Y(f)|²] = |X(f)|² · |H(f)|²  ≈ const · |H(f)|²

→ 出力スペクトルの形が直接 |H(f)| を示す
→ 時間平均（積分）すれば共鳴ピーク・幅・分裂が一目で見える
  • 長所: 逆フィルタ / deconvolution 不要。出力 WAV を STFT して時間平均するだけで |H(f)|² 推定が得られる。Linear chirp の STFT 2D 画像のような「時刻 t で f(t) が駆動された」 という時間-周波数対応関係を意識せずに済む
  • 長所: 全帯域を同時に常時励振するため、共鳴は時間方向に蓄積（リング）し、 定常状態でピークが鮮明に出る。「狭帯域に集中投下しないと SNR が出ない」陥落を避けられる
  • 長所: 実装が最も単純（xorshift32 などで疑似乱数生成 → I²S DAC へ）。 既存 dummy_audio.c の残響合成ジェネレータが 流用可能
  • 長所: 状態変化中の応答変化も観察できる（連続励振中に STFT を取れば 「時間 × 周波数 × 状態」の 3 次元データになる）
  • 短所: クレストファクタが高い（Gaussian noise は piano forte 比 ~12 dB）→ SPK 飽和を避けるため平均パワーを抑える必要、または PRBS（疑似乱数 2 値）に置換して クレスト 0 dB に
  • 短所: 1 周波数あたりの SNR は同パワーの単一トーンより低い → 積分時間（1–3 s）が必要
  • 短所: 連続的に「シャーッ」と鳴る → 本番運用（UX）にはやや不向きだが、 discovery フェーズ（オフライン）では問題なし
  • NN への渡し方: 時間平均した |H(f)|² ベクトル（1024 bin）、または STFT 2D 画像で 時間方向の蓄積過程も含めて学習
MLS / Schroeder（§2.4）との違い: どちらも「雑音的な信号」だが、§2.4 は循環相関で RIR を抽出するための決定論的疑似乱数で 時間軸の遅延構造（位相情報）を取り出す。本節 §2.7 は 定常スペクトル観測だけが目的で、 位相を捨てて |H(f)| のみを得る簡素なアプローチ。実装は §2.7 のほうがずっと軽く、 ROI 発見だけなら §2.7 で十分。

3.A SPK・マイクのキャリブレーション — 自由音場での SPK プリ・エンファシス

機材特性のディップで共鳴を見落とすリスク: どの走査音方式を選んでも、マイクで観測される信号は Y(f) = H_spk(f) · H_room(f) · H_mic(f) · X(f) という積になっている。 MAX98357A + 0.25 W スピーカ + INMP441 のセットには 必ず固有の周波数応答ムラがあり、 ディップ（SPK が弱い周波数）の場所では 本来そこにあるはずの共鳴ピークが埋もれる。 状態判別を行う前に このムラを補正して、SPK が空間に放射する音を平坦化する。

3.A.1 キャリブレーションの考え方

ホワイトノイズを SPK から出して mic で記録し、SPK + mic の合成周波数応答 |H_spk · H_mic| を測定する。記録スペクトルがホワイトノイズより低い帯域 = 機材が弱い帯域なので、 SPK 駆動信号の その帯域だけを事前にプリ・エンファシス（boost）しておくことで、 放射される実音は平坦に近づく。 

1. 自由音場でホワイトノイズを SPK 駆動 → mic 記録
2. |Y_cal(f)|² を時間平均で得る（SPK・mic の合成応答 × const）
3. プリ・エンファシスフィルタ:
     EQ_pre(f) = √( target_flat / |Y_cal(f)|² )
   = 弱い帯域を持ち上げ、強い帯域を抑える形
4. 本運用ではこの EQ_pre を SPK 駆動信号に畳み込んでから送信
   → SPK が放射する音 ≈ 平坦
   → mic 記録は H_room(f) のみを反映（機材ムラがキャンセル）

3.A.2 自由音場での計測が 必須 — ハウスから外して行う

ハウス模型内で計測してはいけない: ハウス模型内には H_room(f) の共鳴ピークが乗っているので、ハウス内で計測した |Y_cal(f)|² には 機材ムラ + 部屋共鳴 が混ざってしまう。 プリ・エンファシスで「部屋共鳴を平坦化する」方向に補正してしまうと、本番運用で 判別したい共鳴特徴を自ら消す本末転倒な結果になる。
項目条件
場所 SPK と mic を ハウス模型から物理的に取り外し、開放空間（無響室 or 反射の少ない部屋の中央、外気下）
SPK-mic 距離 30–50 cm 程度に固定。本番運用での距離と近い値を選ぶ（近接界の影響を揃える）
周囲反射 SPK・mic から 1 m 以内に大きな反射面を置かない（壁・床から離す、絨毯やフォームで吸音）
家庭環境での代替（推奨） 布団を SPK + mic にすっぽり被せるのが最も簡易な準無響条件。布団の繊維で 500 Hz–10 kHz の反射が大幅減衰し、無響室に近い静特性が得られる。重ねる枚数・密度で 効果調整可能。コタツや押入れの中も使える
励振信号 PRBS または Gaussian 白色雑音、3–5 秒連続
記録 → 解析 16 kHz / 24-bit WAV、PC 側で STFT → 時間平均 → |Y_cal(f)|²

3.A.3 SPK 側プリ・エンファシスフィルタ設計

測定した |Y_cal(f)|² から、SPK 駆動信号に畳み込むプリ・エンファシスフィルタを設計する。 

EQ_pre(f) = √( median(|Y_cal|²) / |Y_cal(f)|² )

# 中央値で割ることで「平均的に強い帯域」を 1.0 基準にし、
# 弱い帯域を boost、強い帯域は若干 attenuate する形に
# 最大 boost 量はクリップ（後述）

3.A.3.1 設計上の注意

  • 最大 boost 量を制限: 弱い帯域を持ち上げすぎると SPK 歪み・過熱の原因。 実用的には +3 〜 +9 dB までに制限。+12 dB 超は SPK 共振や TIM 歪みを誘発する恐れ
  • 物理的に出ない帯域は諦める: 100 Hz 以下や 12 kHz 以上で SPK が応答しない帯域は どんな boost を入れても出ない → EQ_pre をフラット（1.0）に固定。あるいは ROI 外として除外
  • 共振点には notch を入れる選択肢: 0.25 W スピーカは特定周波数に大きな共振ピークを持つことが多い。 そこをフラット化するために負の boost（notch）を入れる
  • 位相は無理に補正しなくてよい: 振幅補正だけで十分。位相も補正すると逆フィルタの遅延が増えて UX 悪化

3.A.3.2 実装方式

実装長所短所
PC で EQ 済み波形を事前生成してフラッシュ格納 MCU 側ゼロ計算、設計自由度最大 EQ を変えるたびにフラッシュ書き換え
MCU 上で biquad カスケードを白色雑音にリアルタイム適用 EQ パラメータを動的に変えられる、CMSIS-DSP 既存 biquad で表現できる EQ 形状は限られる
MCU 上で FFT-IFFT 経由（PowerQuad 利用） 任意の |EQ_pre(f)| を実現可 遅延 1 フレーム、実装が一番重い

3.A.4 実装手順

  1. 機材取り外し: ハウス模型から SPK と mic を物理的に取り外し（マウントは脱着可能設計が前提）、 自由音場条件にセット
  2. キャリブレーション計測: ホワイトノイズ Ping を 3–5 秒、3 回繰り返し （温度・SPK ウォームアップの影響を排除）
  3. EQ 設計: Python (scipy.signal) で |Y_cal(f)|² 時間平均 → 上記式で EQ_pre(f) を計算 → 1024 タップ FIR or 8 段 biquad で実装
  4. EQ 保存: captures/calibration/eq_spk_pre.npy or firmware/shared/include/spk_eq_coeffs.h として保存
  5. 機材再装着: SPK と mic をハウス模型に戻す（マウント位置を厳密に再現）
  6. 本番運用: ホワイトノイズ / マルチトーン / Linear chirp など全ての走査音に EQ_pre を畳み込んでから SPK 駆動
  7. 再キャリブレーション: SPK 経年劣化や温度変化で応答が変わるため、月次〜年次で再実施

3.A.5 自由音場 EQ と「全閉基準」差分の使い分け

本節 §3.A は機材自体のムラ（H_spk · H_mic）を補正するためのもので、 ハウス模型固有の 全閉時の H_room は別の話。両者は補完関係。

補正場所目的頻度
§3.A SPK プリ・エンファシス SPK 駆動信号側（emission） SPK + mic 自体の周波数応答ムラを補正 機材取付け時 + 月次〜年次
全閉基準正規化（オプション） mic 記録側（解析） ハウス模型固有の定常応答をベースラインとして引く 設置先ごと + 環境変化時

プリ・エンファシスだけでも実用的には十分なケースが多い。差分が小さすぎる （状態変化が背景の数 % にしか出ない）場合のみ、全閉基準正規化を追加する。

4. 推奨戦略 — まず最小検証 → その後の本格展開

Day 0 サニティチェック — 「3 パターン × 1 サンプルで差が見えるか」（最優先）:
いきなり 14 状態 × 30 サンプルの本気の収集に走るのは 無駄。 まず以下の 2〜3 パターンを 1 回ずつ取り、データ展開方法を変えながら 「目で見て差が出る表現」を探す。これで差が出ない表現を 14 状態に拡張しても判別不能のままで、 そこから先の議論はすべて無意味になる。

  • 🤔 差は見えるが微妙 → さらに 2〜3 サンプル取って再現性を確認し、判断保留

4.1 Linear chirp + STFT 2D 画像化 のアイディア

用途で使い分け: 「どの周波数が共鳴しているか」だけが知りたいなら §2.7 ホワイトノイズ + 出力スペクトル直読 が最短路（時間平均で |H(f)|² 推定が一発で取れる）。本節 §4.1 の STFT 2D 画像化は 時間軸の構造（モード立ち上がり・減衰）も同時に見たい場合に有効で、 NN 入力にも 2D 画像としてそのまま渡せる利点がある。

探索フェーズでは、Linear chirp 中の FFT 時系列を 2D 画像（STFT スペクトログラム）として残し、 時間軸 × 周波数軸の 2D 表現で解析する案が筋がいい。

  • 掃引中の応答が時間軸に展開される — Linear chirp はある時刻 t で周波数 f(t) を駆動するので、 マイク側のスペクトログラムを見ると「t における f(t) の応答」が縦に並ぶ。共鳴がある周波数では そこに 明るい垂直ストリーク が走り、ダンピングの違いがストリーク幅に現れる。 モード分裂（扉が開いて結合）は 並走する 2 本のストリーク として直接見える
  • 解析が「画像を見る」操作になる — 1D log-mag スペクトルでは積分されて消えた情報 （どの周波数がいつ立ち上がってどう減衰したか）が、2D 画像では空間的に残る
  • 共鳴探索の自動化が容易 — 2D 画像上の局所最大やストリーク検出で マルチトーン周波数候補を自動抽出できる

4.2 STFT 2D 画像をそのまま画像分類モデルに食わせる選択肢

さらに、抽出した 2D 画像を画像クラス分類モデル（小型 2D CNN）の入力に直接使う という方向もある。STFT を「画像」として扱い、SqueezeNet/MobileNet 系の縮小版や カスタム小規模 2D CNN で 14 状態を分類する。これは NN 考察 §3.2 で詳細を議論する。

  • 長所: 時間-周波数両方向の局所性を 2D CNN が学習できる、画像処理コミュニティの 既存ノウハウ（拡張・転移学習）が転用可能
  • 短所: MCXN947 NPU の 2D conv は 1D conv より重い、モデルサイズが膨らみがち、 INT8 量子化との相性は要検証
  • 判断材料: 共鳴探索フェーズの 2D 画像を眺めて、「この画像なら 1D に縮約しても情報が残るな」 と感じるなら 1D で進む。「2D で見ないと判別できない時間構造がある」なら 2D CNN へ

4.3.1 同時放射が抱える 2 つの罠

  • クレストファクタ問題: N 個の正弦波を全部位相 0 で足すと、ピーク振幅は N 倍だが RMS は √N 倍しか伸びない → ピーク/RMS = √N。これでは SPK 最大出力 / SNR が極端に悪い。 Schroeder 位相（φ_k = -π·k(k-1)/N）で位相をランダム化すれば crest ~3 dB 程度まで下がり、 平均パワーを実質的に √N 倍稼げる
  • 相互変調歪み（IMD）: 0.25 W スピーカは小振幅でも非線形性があり、 周波数 f₁, f₂ が同時に駆動されると f₁±f₂, 2f₁±f₂, ... に新しいピークが現れる。 本来共鳴がない周波数に偽ピークが立つ → 状態判別を惑わす。順次放射ではこれが原理的に起きない

4.3.2 順次放射が抱える 1 つの罠

  • 計測時間の長さ: UX 上「Ping → 結果表示が 1 秒以内」を目標にすると、 16 周波数 × 50 ms = 0.8 s で目一杯。32 周波数だと 1.6 s で確実にオーバー。 1 トーンあたりの時間を短くする（50 ms → 20 ms）と SNR が落ちる → 共鳴の Q 値が高ければ 立ち上がりが遅く、短時間では定常応答に届かない可能性

4.3.3 推奨方針

  1. Day 0 / 探索フェーズで両方試す: 同じ ROI 周波数群を「同時放射」と「順次放射」両方で計測。 判別性スコア（§6.1）が同等なら同時、明らかに差があれば順次へ
  2. 同時放射を採用する場合の必須対策:
    • Schroeder 位相で crest 低減
    • SPK 駆動レベルを順次の 1/√N 程度に下げて IMD 発生を抑制
    • FFT 解析時は ROI 周波数ごとに 狭帯域窓を取って近接ピークの混入を避ける
    • 探索フェーズで IMD が発生する周波数ペアを予測（f₁+f₂, f₁-f₂ が他の ROI に近接していないか）して 危険なペアは順次に分離
  3. 順次放射を採用する場合: §2.6 ゲート式バーストスイープと実質同じ実装になる。 既存の pulse 型パターンライブラリで対応可能
  4. サブグループ段階放射が現実的な折衷: 4–6 周波数を 1 グループにまとめ、 グループ内は IMD が ROI と干渉しないよう 非倍音関係（周波数比が無理数に近い）に選ぶ。 4 グループ × 100 ms = 400 ms で済み、SNR も実用的

4.4 推奨本番方式: ROI 圧縮ゲート式バーストスイープ（マルチトーンより筋がいい）

結論先取り: ROI で 16–32 周波数を特定した後の本番計測には、 マルチトーン同時放射ではなく、ROI 周波数だけを順次撃つゲート式バーストスイープを採用するのが筋。 §2.6 ゲート式バースト（22 s）の弱点だった「時間がかかりすぎ」が ROI 圧縮で解消される一方、 §4.3 マルチトーン同時放射の罠（IMD・クレストファクタ）を全部回避できる。

4.4.2 シーケンス設計

ROI で抽出した 16 周波数 {f_1, f_2, ..., f_16} に対し:

時刻 t:
[f_1: ON 30ms][OFF 30ms][f_2: ON 30ms][OFF 30ms]...[f_16: ON 30ms][OFF 30ms]
 ─────── 32 区間、合計 960 ms ───────

各 OFF 区間で:
  decay_rms[k] = RMS( y(t) over OFF_k の最初 20 ms )
  → 16 次元の特徴ベクトルが 1 計測で得られる

NN への入力:
  16 次元の振幅ベクトル → 極小 MLP (§3.6) で 14 状態分類

4.4.3 ON / OFF 時間の選び方

時間配分ON 時間OFF 時間合計用途
高速 20 ms 20 ms 16 × 40 = 640 ms UX 重視、Q 低めのモードでも RMS は読める
標準 30 ms 30 ms 16 × 60 = 960 ms UX 許容内、Q ≈ 10 程度のモードまで定常応答に届く
精密 50 ms 100 ms 16 × 150 = 2.4 s Q 値も精密に抽出（exp 減衰フィット）

ON 時間の下限: 共鳴 Q 値が高いモードほど定常応答到達に時間がかかる。Q = 10 のモードなら 立ち上がり時定数 τ ≈ Q/(π·f) で、f=572 Hz なら τ ≈ 5.6 ms → 30 ms ON でほぼ定常に達する。

OFF 時間の下限: 高 Q モードほど減衰も遅い。f=572 Hz, Q=10 で 60 dB 減衰に約 30 ms。 20 ms OFF だと完全減衰せず次のトーンに残響が混入する可能性 → 標準 30 ms 以上推奨。

4.4.4 さらなる短縮アイディア

  • ROI を 8 周波数に絞る: 16 → 8 にできれば合計 480 ms。判別性スコア上位だけ採用
  • 非倍音ペアで 2 周波同時 OFF 観測: f₁ ON → f₁+f₂ 同時 OFF（f₁ と f₂ が非倍音関係なら IMD 軽微）→ f₂ ON のように 交互ずらしで時間圧縮。実装複雑化するため標準採用は見送り
  • 適応的サンプリング: 高 Q モードだけ長く ON/OFF し、低 Q モードは短時間で済ませる

4.4.5 §3.6 マルチトーン MLP との接続

本方式の出力は 16 次元の周波数別 RMS 振幅ベクトルになるため、そのまま NN 考察 §3.6 マルチトーン入力 × 極小 MLP の入力として使える。 「マルチトーン」と書いてあるが本質は「16 周波数の振幅ベクトル」なので、生成元が同時放射でも順次バーストでも NN 側の構造は変えなくてよい。本番運用ではゲート式バーストの出力ベクトルを MLP に流すのが推奨経路。

4.5 4 ステップに分解した進め方

  1. 第 1 段: Linear chirp で 14 状態 × 30 サンプル取得 — MCU は既存 chirp 生成器を使えるので 実装最簡。pc/collector_client.py が WAV + 真値ラベル CSV を保存
  2. 第 2 段: PC 側で STFT 2D 画像化 + 可視化 — Python (librosa / scipy) で 各サンプルの STFT を計算し、ヒートマップとして 14 状態をパラパラ眺める。 どの帯域・どの時刻に状態依存の差が出るかを目視で特定
  3. 第 3 段: 2 系統で並走

6. 判別性解析の手法 — どの周波数が状態判別に効くか

Day 0 サニティチェックや本格的なキャラクタリゼーションで得たデータから、 「どの周波数（または STFT 2D 画像のどの領域）が状態判別に効くか」を定量化する。 以下は旧「励振パターン設計」ノート §6 から統合した方法論で、ゲート式バーストや Linear chirp の応答どちらにも適用できる。

6.1 判別性スコア（inter-class / intra-class 分散比）

各周波数 f について:
  inter_var(f) = Var across N states           # クラス間分散
  intra_var(f) = Mean of within-state Var       # 同一状態の繰り返し間分散
  discriminability(f) = inter_var / (intra_var + ε)
  • 分母: 同じ状態を繰り返し測ったときのばらつき（再現性の悪さ）
  • 分子: 状態を変えたときのばらつき（識別したい情報量）
  • 比が大きい周波数ほど「再現性がよく、状態で大きく動く」 = 判別に効く
  • 上位 N（例: 16–32）周波数をマルチトーン Ping の候補として抽出

6.2 早期判定基準（PC 側可視化）

全 14 状態の判別性を見る前に、まず「全閉 / 窓 a 単独開 / 扉 AB 単独開」の 3 状態だけを 重ね描きする（§4.0 Day 0 と同じ）。

  • 明らかに違う周波数がある → 全体方針成立、本格収集と targeted Ping 設計へ進む
  • 状態間で違いが小さい → CNN を訓練する前に 物理層で破綻が見える。 マイク/スピーカ位置を変えて再採取、または模型形状を見直す

6.3 ターゲット励振の予測検証

Phase 1 の生データ（広帯域応答）から、Phase 4 で使う予定のマルチトーン Ping の応答を numpy で 再合成できる（線形性が成り立つ限り）。

  • Phase 1 の応答から targeted_v1 で得られるはずのスペクトルを再構成
  • その擬似データで簡単な線形分類器を学習 → 交差検証 AUROC を計測
  • 予測 AUROC < 0.90 なら top N を 32 に増やす、選定方法を見直すなど Phase 4 の本収集に進む前に調整できる
