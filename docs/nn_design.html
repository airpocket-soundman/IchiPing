NN 詳細設計 — IchiPing v1 (DigiKey)

14-class softmax 1D-CNN（観測等価クラスを直接出力する単ヘッド構成）。 spec.html §4.3 を踏襲しつつ、 pc/training/model.py の実装と features.py の前処理を結びつけて、 NPU 上での INT8 推論まで一気通貫で説明する。
~13 K params ~13 KB INT8 14 クラス softmax MCXN947 NPU ターゲット

アーキテクチャ全体

3 層の Conv1D backbone + Global Average Pool + 単一の全結合層 (64→14) + softmax。出力 = 14 観測等価クラス (A1, A2, B1..B4, C1..C8) を直接予測する。

なぜ 14-class softmax 単ヘッドなのか — 理論的根拠

結論: 観測情報量上限 $I(\text{観測}; \text{真状態}) \le \log_2 14 \approx 3.81$ bit と 出力エントロピー上限が一致する。これは情報理論的に「無駄なし・捏造なし」の最適構造。

IchiPing は 5 サーボ × open/close = 32 真状態を持つが、ドアによる遮蔽で 音響的に区別不可能な等価クラスが生じ、観測可能な区別は最大 14 クラスに縮退する （詳細: 14 等価クラス解析）。 これは物理から導かれる hard constraint で、学習で破れない。

候補アーキ出力次元$H(\text{出力})$ 上限チャネル容量との差判定
14-class softmax14$\log_2 14 \approx 3.81$ bit一致（無駄なし）★ 本命
32-class softmax32$\log_2 32 = 5$ bit+1.19 bit（ノイズから捏造）科学検証用
6-head 混合 (sigmoid + softmax)~216$\log_2 216 \approx 7.75$ bit+3.94 bit退避（連続角度時代の遺物）

容量超過のビットは、データのノイズ成分にフィットさせるしかない。32-class は同じ等価クラス内 4 状態に対し posterior を均等分割すべきところを、訓練データの偶発的バイアスから「どちらかに振る」よう学んでしまう。 これは情報理論的に有害で、有限データ域では汎化を阻害する。

ベイズ最適分類器の観点からも 14-class が直接 $P(\text{equiv\_class}_k \mid x)$ を表現する。 バイアス-分散トレードオフでも、VC 次元の小さい 14-class の方が同データ量での汎化誤差が小さい。

32-class 変種の存在意義

本命は 14-class だが、観測可能性予言の経験的検証のために 32-class softmax variant (model_32cls.py) を併設する。 予言通りなら test acc が ~0.44 (= 14/32) で頭打ち、32×32 confusion で 4×4 等価ブロックが 浮かび上がるはず。これは仮説検証の 1 回限りの実験であり、本番モデルには使わない。

各 Conv の後に BatchNorm1d + ReLU。BN は INT8 量子化時に Conv に畳み込めるため 推論時は実質ゼロコスト。padding は kernel/2、stride で空間方向を段階的に圧縮し、 最後に AdaptiveAvgPool1d(1) で時間軸を畳む（→ 64-d shared embedding）。

出力ヘッド FC 64→14 + softmax

共有 backbone から 64-d embedding を受け、単一の全結合層 (weights 64×14 = 896, bias 14) で 14 等価クラスのロジットに射影し、softmax で確率分布を得る。損失は標準的な cross-entropy 1 本。

データ収集時のラベルは 5-bit (a, b, c, AB, BC) だが、訓練前に等価クラス index に変換する。 この変換は pc/training/dataset.py の STATE_TO_EQUIV table で行う。

完全な等価クラス定義表は Full 32 初期計測 §等価クラス一覧。 16 + 8 + 4 + 8 = 36 ≠ 32 に見えるが、A1/A2 は重複なく分割される (16 + 8 = 24) ので最終的に 24 + 4 + 8 = 32 真状態が 14 クラスに分割される。

32-class 変種（科学検証用）

本命の 14-class とは別に、単一の 32-class softmax ヘッドを持つ variant IchiPingV1_32cls を model_32cls.py に併設 （backbone 同一）。観測可能性予言の経験的検証用で、本番モデルではない。

予想結果: full_32_v1 で A2 クラス内 8 メンバーの RMS std は 800-6000 Hz 帯で 0.07 dB（雑音床と同オーダー）。クラス内シグナルはほぼ無く、 32 クラス test acc は ~0.44 (= 14/32) で頭打ちになると見込む。 32×32 confusion matrix で 4×4 等価ブロックが浮かび上がれば予言通り。詳細: 学習計画 §2.5。

退避: 6-head 混合（連続サーボ角度時代の遺物）

過去案: sigmoid (binary / [0,1] 連続) + 3-class softmax の 6-head 混合。 当初はサーボ角を連続値で扱う想定だったため設計されたが、現ラベルは binary 開閉のみで、 6-head の出力空間は 216 通り → そのうち実在は 32 → 観測可能は 14 という二重の縮退を NN に強いる構造で情報理論的に非効率。2026-05-22 に正式廃止、 将来サーボを連続角度で動かす計画が復活した場合の参考として model_legacy_multihead.py に退避予定。

特徴抽出パイプライン（PC と MCU で共通設計）

PC 側は features.py で同じ手順を踏む。 MCU 側は同じ流れを PowerQuad-FFT で実装する（DSP コプロセッサで 2048-pt rFFT を ms オーダーで完了）。 訓練と推論で 入力の生成手順が完全に一致することが、INT8 量子化後の精度を保つ鍵。

初期計測で観察された特異点 (full_32_v1)

クラス A2 内に 2 つの外れ値: s10100 / s11000: Linear chirp で全 32 状態を 1 ショットずつ取得した full_32_v1 解析で、観測等価クラス A2 （扉 AB 閉 × 窓 a 開、メンバー 8 個）の中で 2 つの状態がクラス内中央値から 系統的にずれていることが判明した。本来このクラスの 8 メンバーは 原理上同一スペクトルになるはずだが:
stateRMS_dB vs A2 中央値max\|Δ\| 周波数ずれの性質
s10100 +5.00 dB 326 Hz 強い peak 差（クラス内最大の外れ）
s11000 +1.58 dB 215 Hz（200-280 Hz 帯に集中） 軽度の dip（低域に系統的減衰）
その他 A2 メンバー (6 個) 1.00 〜 1.46 dB 多様 クラスタとして tight

原因仮説 — 外部雑音の可能性が最有力

  1. 外部雑音の影響（最有力）: max\|Δ\| のピーク周波数が両者とも 200-330 Hz の低域に集中しており、ここは
    • SPK (45 mm, 0.25 W) の物理的出力が弱い帯域
    • 外部生活雑音（空調・通行音・低周波振動）が乗りやすい帯域
    • chirp の開始周波数 200 Hz 直後の遷移帯
    が重なる「計測ノイズが本物の信号を上回る領域」。同じデータでも 400 Hz 以上に限定して RMS を再計算すると、A2 クラス内の std が 0.316 → 0.072 dB と 4.4× 改善し外れ値が消える。これは「外れ値の正体は低域雑音」という 仮説を強く支持する。
  2. 扉 AB の遮音不完全: 仮説 1 が違う場合、扉 AB の物理的な隙間から 向こう側の窓状態が漏れて見えている可能性。s10100 は窓 c 開、s11000 は窓 b 開、 両者とも「向こう側の窓が開いている」状態で、観測等価性が崩れている方向。
  3. サーボ機械的ばらつき: SG90 の位置決め精度 ±2° 程度の差で 模型の小開口部が微妙に変わる可能性。

14-class softmax 学習のコツ

  • クラス不均衡対策: A1 (全閉) は 32 状態のうち 16 個 (50%) を占める一方、B1..B4 / C1..C8 は各 1 個ずつ。 収集データもこの分布になるので、訓練時に class_weight 設定（逆頻度 or effective number of samples）または クラスバランス サンプリングを使う。
  • 未経験状態 holdout の評価を必ず別途取る。例えば C 系列のうち 1 状態を holdout にし、 他 7 状態だけで訓練して holdout で評価する。等価クラス内の汎化が破綻すると spec §11 の v1 主張が崩れる。
  • OOD 検出: any_open の代わりに softmax の最大確率や entropy を OOD スコアとして使える。 雑踏環境で全クラス確率が均等に低い → 未知音と判定。
  • 32-class variant も同時訓練: 同じ backbone で 32-class head を訓練して 32×32 confusion を取り、 14-class 等価ブロックが浮かび上がるか確認する。これが観測可能性予言の経験的検証になる。
