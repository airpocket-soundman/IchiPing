1. 直近で実行する計測 (1 時間以内) 全 DONE

DONEStep A — 静寂 vs TV 雑音床の比較計測

所要 ~30 分（計測 1 分 + TV ON/OFF 切替 + 解析）

開発環境（個室）と展示会場想定（TV 再生中）の 2 条件で SPK 駆動なしの silence 計測。雑音床スペクトルが帯域別にどう変わるかを直接観測。 

cd D:\workspace\github\IchiPing\pc

# A-1: TV OFF
uv run python collector_client.py --port COM3 `
    --plan plans/silence_quiet.yaml --run-id silence_2cond_v1

# A-2: TV ON、通常音量、模型から 1-2 m
uv run python collector_client.py --port COM3 `
    --plan plans/silence_tv.yaml --run-id silence_2cond_v1

# A-3: 解析
uv run --extra training python analyze_noise.py

得られる判断材料:

  • captures/silence_2cond_v1/analysis/ に 5 枚 PNG
  • TV 条件下で雑音増加 dB が大きい帯域 → ROI から除外候補
  • chirp 信号との SNR マップ → 20 dB 以上の帯域が「使える領域」

DONEStep B — ホワイトノイズで 32 状態取得

所要 ~5 分（計測のみ）

chirp 計測と同条件（静か、volume 3、5 サーボ全配置）で、励振方式だけを PRBS 2 秒に変えて 32 状態を取得。chirp との比較材料。 

uv run python collector_client.py --port COM3 `
    --plan plans/full_32_noise.yaml --run-id full_32_noise_v1

# 解析（既存スクリプトで OK）
uv run --extra training python analyze_full32.py `
    --root captures/full_32_noise_v1

DONEStep C — chirp vs ホワイトノイズ 比較解析

所要 ~10 分（既存 PNG を並べて目視 + 数値比較）

Step A + B 完了後に、両方のデータでの判別性を比較。 具体的には:

  • 同じ等価クラス内の RMS dB ばらつき → 安定性
  • 異クラス間の RMS dB 差 → 判別性
  • 外れ値 s10100/s11000 の有無
  • 各条件 (TV あり/なし) での SNR

→ 「chirp or ホワイトノイズ」を本命に確定

2. 現在未決定の項目

DONED-1. 走査音方式 — chirp / white noise

どちらも 200-6000 Hz 帯域をカバーできる。判断は実測比較 (Step A-C) 後に。 現時点の仮判定:

観点chirpホワイトノイズ
2D STFT で時間-周波数構造◎ 直線として可視化△ 統計的に定常、時間情報なし
1D 時間平均 FFT○ 利用可◎ 自然な表現（|H(f)|² 直読）
解析パイプライン整合フィルタ要FFT 平均だけ
SPK 駆動線形掃引、瞬間的単一周波数全帯域同時駆動、低クレスト (PRBS)
雑音耐性整合フィルタで +30-45 dB SNR時間平均で √N の減衰
実装複雑度低最低

判定基準: Step C の比較で クラス内ばらつきが小さい方を採用。同等ならホワイトノイズ優位 （解析が単純、雑音と同種なので扱いやすい）。

解決: chirp + baseline diff + Welch FFT を採用（noise / passive は cross-day 汎化で劣る）。 詳細は full32_noise_test / full32_passive_test。

DONED-2. 本番運用励振 — マルチトーン or ゲート式バースト

ROI 確定後の本番運用方式。現時点の見立て:

観点マルチトーンゲート式バースト
計測時間~100 ms (高速)~800 ms (16 周波)
雑音耐性△ IMD で偽ピーク◎ OFF 区間で雑音床直接計測
per-freq SNR 判定不可（同時駆動のため）◎ ON/OFF で per-frequency に判定
SPK 出力効率クレストで損◎ 単音、フル振幅
NN 入力との接続振幅 16 dim ベクトル同（同形式）

現時点の仮選択: ゲート式バースト（雑踏運用必須 + UX レイテンシ 1 s 許容）。 マルチトーンに振るのは ROI が「2-3 周波数の狭帯域」に収束した場合のみ。

解決: 不採用。chirp 2 秒 1 ショット + baseline diff で必要十分な SNR と cross-day 汎化が得られたため、追加の励振工夫は不要となった。

DONED-3. ROI 帯域の最終確定

現時点の仮判定: 500-6000 Hz（400 Hz 以下は外部雑音と SPK 弱域が支配）。 Step A の雑音床解析と Step C の判別性解析を見て確定。 ROI 確定後にマルチトーン用の 8-16 周波数選定 (§4.4 の判別性スコア最大化) に進む。

解決: ROI を固定帯域で切らず、Welch スペクトル全帯域を NN 入力に渡す方式に変更。 NN が学習で重要帯域を獲得し、baseline jittering augmentation で外乱を吸収する設計とした。

3. 確定済み事項（参考）

DONE等価クラス理論

32 真状態 → 14 観測等価クラスに集約される（マイク Room A、扉 AB / BC 閉塞による）。 詳細: Full 32 初期計測 §2。

DONEDay 0 サニティチェック — 仮合格

chirp 励振で 32 状態を取得し、等価クラス予言と実測 RMS_dB がほぼ整合 （A2 の s10100 / s11000 に外れ値あるが 低域 200-400 Hz の外部雑音由来の可能性大、 Step A の無音計測で確認予定）。本格展開に進める判断。

DONESPK EQ + ホワイトノイズ実装

ファーム側に EQ (8 段 biquad cascade, デフォルト OFF) + PAT NOISE コマンド追加済。 PC 側に calibrator.py + analyze_noise.py / analyze_full32.py 実装済。 詳細: 09_collector/README §EQ。

4. 後で詳細化する項目

v1.5配置先 PC 再学習による雑踏適応

展示会場で 環境ノイズ 30-60 秒録音だけ 取り、PC でオフライン augmentation + FC ヘッド fine-tune (backbone freeze) で適応モデル生成、 USB CDC 経由で MCU flash に書込。所要 ~10 分の運用フロー。

詳細化は v1.0 確定後。MCU 上での追加学習は NPU の制約上不可能だが、 PC 経由でのこのフローは十分実用的。 関連: NN 考察 §7 v1.5。

v0.6+整合フィルタによる chirp デコンボリューション

chirp 採用が確定した場合の signal-processing 強化。scipy.signal.fftconvolve で時間反転 chirp と畳み込み → 線形 RIR を抽出 → 雑音 √N 抑制。 Step C で chirp が選ばれた場合に pc/analyze_full32_matched.py として実装。

v0.6+repeats=5 で再計測 + 中央値集約

1-shot 計測のばらつきを排除する基本対策。本命走査音方式が決まったあと、 本データセット (label data for NN training) を取り直すフェーズで plans/gen32.py の REPEATS = 5 に変更して全 14 等価 クラス × 30 サンプル相当を再取得。

物理改善模型の遮音強化

A2 等価クラス内で s10100 等のずれが 1 dB レベルで残る場合の対策。 扉 AB / BC のパネルにゴムガスケットを足す、外側に制振フォームを内貼り。 Step A + Step B 後の判断。
